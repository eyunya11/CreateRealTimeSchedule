# CreateRealTimeSchedule

Minecraft 1.21.1(NeoForge)用の [Create](https://modrinth.com/mod/create) アドオンです。現実の時刻表どおりに列車を走らせるための MOD です。

現実と同じ速さで進む時計と、その時計で出発時刻を決める時刻表の待機条件「Real Time of Day」を追加します。早く着いた列車は出発時刻まで待ち、遅れて着いた列車は最短停車時間だけ止まって出ます。遅れは、停車時間を詰めて取り戻します。

状態: 開発の初期段階です(0.1.0-SNAPSHOT)。時計、空の同期、待機条件、[ダイヤでの運行](#ダイヤでの運行)は動いていて、テストもあります。確認の範囲は[確認していること、いないこと](#確認していることいないこと)にまとめました。コマンド名は変わるかもしれません。このあとの計画(ダイヤグラム、ダイヤの編集ページ、待避)は [docs/proposal.md](docs/proposal.md) にあります。

English: [README.md](README.md)

## 必要なもの

- Minecraft 1.21.1 と NeoForge 21.1(21.1.262 でビルドしています)
- Create 6.0.10 以上
- サーバーと、すべてのクライアントの両方に、この MOD が必要です。新しい待機条件を含む時刻表は、MOD がないと読めません。

## 時計

時計の値は、ゲーム時間にワールドごとの offset(ずれ)を足したものです。20 tick が1秒で、1日は現実の24時間(1,728,000 tick)です。バニラの1日の72倍の長さになります。

- 数えるのは tick で、現実の壁時計ではありません。そのため、列車とずれず、サーバーを一時停止や停止している間は止まり、`/tick rate` で速さを変えると同じだけ速くなります。サーバーの tick が毎秒20を下回ると、時計も現実の時刻より遅れます。
- 保存された時計がないワールドでは、`start_time`(既定は 06:00)から始まります。
- 24時間動かし続けるサーバーなら、時計は現実の時刻に近いままです。再起動のたびに、止まっていた時間のぶんだけ遅れます。`/rtclock align` か、`align_on_start` の設定で、サーバーの時刻に合わせ直せます。

| コマンド | 使える人 | 内容 |
| --- | --- | --- |
| `/rtclock get` | 全員 | 時計の日数と時刻を表示します |
| `/rtclock set <時:分[:秒]>` | オペレーター | 日数はそのままに、時刻を設定します。待機中の列車は新しい時刻に従います。時刻を進めれば列車は出発し、戻せばその分長く待ちます |
| `/rtclock align` | オペレーター | 時刻をサーバーの時刻に合わせます |
| `/rtnetwork export` | オペレーター | 線路網の駅と、駅の間の所要時間(燃料のない列車の全速)を、ワールドフォルダーの `createrealtimeschedule/network.json` に書き出します。これから作るダイヤの編集ページで使うためのものです |

## 空

既定では、空も時計に合わせます。12:00 が正午、0:00 が真夜中で、月の満ち欠けは現実の1日ごとに進みます。そのために、ゲームルール `doDaylightCycle` を off に保ち、毎 tick に昼夜の時間を時計から設定します。そのため、次のようになります。

- ベッドで寝ても夜は飛びません。`/time set` は、次の tick で元に戻されます。
- 昼夜の長さを変える他の MOD とは併用できません。併用するなら `sync_sky` を `false` にしてください。
- `sync_sky` を `false` にすると、空はバニラに戻り、`doDaylightCycle` も元の値に戻ります。
- `sync_sky` が true のまま MOD を外すと、`doDaylightCycle` が off のまま残ります。外す前に `sync_sky` を `false` にしてワールドを一度開くか、外したあとに `/gamerule doDaylightCycle true` を実行してください。

## 待機条件「Real Time of Day」

時刻表の画面で、停車駅に条件を足し、種類に「Real Time of Day」を選びます。設定の行には、次の三つがあります。

- 列車が出る時刻(時と分の上でスクロール)。たとえば 08:10。
- 最短停車時間。0秒から10分まで。新しい条件は、`default_minimum_stop_seconds`(既定は20秒)から始まります。
- 時刻を繰り返す間隔。毎日、または12・6・4・3・2・1時間ごと、45・30・15分ごと。08:10 を15分ごとにすると、毎時の :10、:25、:40、:55 に出発します。

列車は、その駅で待ち始めたときに、出発時刻を一度だけ決めます。出発時刻は、自分の出発枠と、遅れて着いた場合の最短停車の終わりのうち、遅いほうです。

出発枠が 08:10、最短停車時間が30秒、定刻の到着が 08:08 の場合は、次のようになります。

| 到着 | 出発 | 停車時間 | 残る遅れ |
| --- | --- | --- | --- |
| 08:08:00(定刻) | 08:10:00 | 2分 | なし |
| 08:09:00(1分遅れ) | 08:10:00 | 1分 | なし(取り戻した) |
| 08:11:00(3分遅れ) | 08:11:30 | 30秒 | 1分30秒 |

出発枠は、時計の「次の 08:10」ではありません。その列車が前の Real Time of Day の停車駅で使った枠につなげて、その後でこの駅の時刻に最初に当たる時刻にします。このため、遅れた列車は次の枠へ飛ばずに、自分の時刻表に対して遅れたまま走ります。1周のうちに同じ時刻を2回指定した場合、2回目は翌日の枠になります。次の場合は、つなげずに、到着に最も近い枠を取ります。前の枠がないとき(時刻表で最初の停車駅のとき、または別の時刻表を入れた直後)と、つなげた枠が到着から繰り返し間隔1つぶん以上離れているときです。

出発時刻は、時計の値として列車に保存されます。そのため、ワールドを保存しても保たれ、`/rtclock set` にも従います。待機中は、列車の状態表示(Create のディスプレイリンクで見せられます)が「Departs at HH:MM:SS」(日本語では「発車時刻: HH:MM:SS」)になります。

## ダイヤでの運行

この MOD は、Create の時刻表を使わずに、1日分のダイヤのとおりに列車を走らせることもできます。ダイヤは、路線、列車、運用を書いた JSON のファイルで、形式は [docs/proposal.md](docs/proposal.md) にあります(第5版。ダイヤは、それを書ける最も古い版で書き出すので、第3版から第5版で足したものを使わないダイヤは第2版になります)。運用は、1本の列車の1日の仕事です。車庫を出て、列車の並びを順に走り、車庫に戻ります。車庫と最初の列車の始発駅の間、最後の列車の終着駅と車庫の間は、回送の列車(`"deadhead": true`)でつなぎます。回送も、ほかの列車と同じく時刻で動きます。このファイルは、ブラウザで開く編集ページで、運行図に線を引いて作れます(下を参照)。

| コマンド | 使える人 | 内容 |
| --- | --- | --- |
| `/rttimetable load` | オペレーター | ワールドフォルダの `createrealtimeschedule/timetable.json` を読み、そのダイヤで運行します。誤りがあれば、その内容を表示し、それまでのダイヤで運行を続けます |
| `/rttimetable status` | オペレーター | 運用ごとに、どの列車が走っているか、どこにいて何秒遅れているか、または次にいつ出るかを表示します。最近うまくいかなかったことも表示します |
| `/rttimetable unload` | オペレーター | ダイヤでの運行をやめます |
| `/rtdiagram` | だれでも | ダイヤの最初の路線の運行図を開きます。`/rtdiagram line <路線>` で、ほかの路線を開きます |
| `/rtdiagram refresh` | オペレーター | 駅の間隔を、すぐに線路から求め直します。線路を変えると、変わらなくなってから5秒後に、サーバーも自分で求め直します |
| `/rteditor copy timetable` | オペレーター | 運行中のダイヤを、編集ページ用にクリップボードに写します(下の2つと同じくクライアントのコマンドです。クリップボードに触れるのはこの3つだけで、自分で打ったときに限ります) |
| `/rteditor paste` | オペレーター | クリップボードのダイヤを読み込みます。`load` がファイルを読むのと同じです |
| `/rteditor copy network` | オペレーター | 線路(駅と所要時間)を、編集ページ用にクリップボードに写します。`/rtnetwork export` は `createrealtimeschedule/network.json` に書き出します |
| `/rteditor` | だれでも | ダイヤの編集ページをブラウザで開きます(クライアントのコマンド) |

- 運用の最初の発車の `duty_lead_seconds`(既定は60秒)前に、車庫の駅でいちばん長く待っている列車を、その運用に入れます。車庫の名前の駅に止まっていて、Create の時刻表を持たず、運用にも入っていない列車が、待っている列車です。
- 発車の時刻になると、Create の行き先の命令と同じやり方で列車を次の駅へ送り、走らせるのは Create です。早く着いた列車は時刻まで待ち、遅れて着いた列車は最短停車時間だけ止まって出ます。規則は待機条件と同じです。最短停車時間は、ダイヤの停車の値、なければ駅の値、それもなければ `default_minimum_stop_seconds` です。
- ダイヤは毎日くり返します。列車がなくなった運用、脱線した運用、Create の時刻表を入れられた運用は中断し、その列車には手を出しません。
- `recovery_threshold_seconds`(既定は10分)より遅れた列車は、列車を運休してダイヤに戻します。遅れた列車が、その運用であとでまた出る駅に着いたときに、途中で取り戻せる時間(最短停車時間を超える停車の分と、線路の所要時間を超える走りの分)では、次にその駅を出るまでに基準以内に戻らないとします。そのときは、その駅で、基準以内で出られる最初のあとの停車まで待たせ、そのあいだの列車を運休します。ダイヤで `"keep": true` を付けた列車を運休することはありません。待つあいだにダイヤの列車がその駅を止まらずに通るとき、その駅に止まりに来る列車の分のホームが足りないとき、時間内に次の駅へ出られないとき(後ろへ走れない列車が折り返す場合など)、そのあとに回送しか残らないときも、待たせません。待たせたことと運休した列車は、`/rttimetable status` に出ます。
- 出発の時刻までに空いた列車がない運用も、すぐには運休にしません。列車が空いたら、ダイヤに戻れる見込みがあるあいだは遅れて出し、遅れが大きければ上と同じように待たせて戻します。見込みがなくなれば、その日は運休です。始まっているはずの時刻のあとにダイヤを読み込んだ運用も、同じように遅れて出します。
- 停車は、発つ前にほかの列車を待てます(ダイヤの `"wait_for"`)。その列車が駅を出るか、止まらずに通るまで待ちます。ダイヤは、定刻なら待たずに済むように組んでください。待ちが列車を時刻より後まで止めるのは、相手が遅れたときだけです。駅に止まる列車を待つときは、その列車が出てから、ダイヤでのその列車の発車から自分の発車までの間を空けて出ます。相手が遅れた分だけ、自分も遅れて出ます。止まらずに通る列車を待つときは、通ったらすぐに出て、その先は Create の信号に任せます。待避線で快速の通過を待つ(本線の駅を選びます)ことも、同じ駅に止まる快速が先に出るのを待つこともできます。その日に走っていない列車と、遅れを戻すために運休した列車は待ちません。どの運用にも入っていない列車や、線路で決まる道筋ではその前にその駅を通らない列車(環状線で反対に回るなど)を待つ設定は、待つ相手がいないので待ちません。そのことは、ダイヤを読み込んだときと `/rttimetable status` に出ます。列車が駅を通ったことは、最後の車両の後ろの端が、その名前の駅を過ぎたことで知ります。通ったと見えないまま次の次の停車に着いたときは、その道にその名前の駅がないということで、そこで待ちを終えます(次の停車では、長い列車の後ろの端が、まだ駅の手前にいることがあります)。環状線でどちら回りかは、線路で決まります。待つのは、自分の発車の時刻から `max_wait_seconds`(既定は5分)か、待ちごとに決めた時間までです。待つ列車がそれより遅れる見込みなら、すぐに出ます。何を待っているかは `/rttimetable status` に出ます。
- 遅れた列車がどれだけ取り戻せるかの見込みには、途中の信号やほかの列車、ダイヤにない列車が入っていません。列車が駅に着くたびに、その時点で判断し直します。
- Create の時刻表を持つ列車には触れないので、同じ線路で一緒に走らせられます。
- 運用を走る列車の列車番号や行き先は、Create の案内板やディスプレイリンクに出ません。案内板が読む Create の時刻表を、その列車が持たないためです。

運行図は、ダイヤの1つの路線を描きます。横軸が時刻、縦軸が路線の駅で、駅の間隔は線路の長さです。ダイヤの列車は細い線で、種別ごとに色が違い、回送は点線です。遅れた列車をダイヤに戻すために運休した列車は、薄く描きます。その営業日の運用が実際に走った線を、太い赤で重ねます(中断した運用は紫)。駅で待たせた列車は、出るまでその駅に止まっている線になります。待ちの相手として見張っている駅を止まらずに通った列車の線は、通った時刻のところで折れます。ほかの列車を待つ停車は、待つ相手がその駅を出る(通る)ところから、待つ列車が出るところへの点線の矢印で描きます。待つ相手が、待つ列車の時刻より後に通るダイヤでは、矢印は時刻を戻る向きになります。その日に運休した列車や、どの運用にも入っていない列車がかかわる待ちは、待たないので薄く描きます。キーでも開けます。操作の設定で「運行図を開く」にキーを割り当ててください。ホイールで拡大縮小、ドラッグで移動、左右の矢印キーで路線の切り替え、Page Up と Page Down で前日と当日の切り替え、Home でいまの時刻に戻ります。サーバーは、終わった運用の時刻を、当日と前日の分だけ持っています。

### ダイヤの編集ページ

編集ページは Web ページです。`/rteditor` は、ページを MOD からゲームフォルダの `createrealtimeschedule/editor` に取り出して開くので、いつも手元の MOD の版のページが開きます。同じページを https://eyunya11.github.io/CreateRealTimeSchedule/ にも置くので、MOD を入れていない人も使えます。ダイヤは次の手順で作ります。

1. ゲームで `/rteditor copy network` を実行し、ページの「線路を読み込む」に貼り付けます。これで、ページが駅と駅の間の所要時間を知ります。
2. 路線を足し、駅を上から順に選びます(周回する路線には「環状線」の印を付けます)。
3. 「列車を描く」を押し、停車する駅の行を順にクリックします。線は線路の所要時間どおりに伸び、それより右をクリックすると、その時刻に着きます。各駅には、その駅の停車時間だけ止まります。着いたあとマウスを右へ動かすと発つ点がついてきて、同じ駅の行をもう一度クリックすると、そこで発ちます。ほかの駅の行をクリックすれば、停車時間だけ止まって次の駅へ進みます。「駅の停車時間」で、駅ごとに停車時間と、遅れたときの最短停車時間を決められます。決めていない駅は、停車時間が設定の値(既定は20秒)、最短停車時間がサーバーの設定になります。描いている間は、右の欄で、その列車がこれから止まる停車時間を決められます。描いた停車の停車時間も欄の表で直せ、後ろの停車も同じだけずれます。描き終えた列車の表では、停車ごとに停車時間と最短停車時間を直せます。ダブルクリックか Enter で描き終えます。着く点をドラッグすると到着の時刻だけが動いて停車時間が変わり、発つ点をドラッグすると停車時間が伸び縮みし、駅の間を走る線をドラッグするとその区間だけが動き、停車している線をドラッグすると列車全体が平行に動きます(Ctrl を押しながらなら、走る線でも列車全体が動きます)。引いて動かした時刻は、15秒ごと(Shift を押している間は5秒ごと。どちらも設定で変えられます)に揃います。引いている間は、動かしている時刻がポインターのそばに、線路の所要時間で走ったときの線が赤い破線で出ます。正確な時刻は右の表で直します。どの直し方でも、駅の間は線路の所要時間より短くなりません。ドラッグはそこで止まり、打ち込んだ時刻は線路が許すいちばん近い時刻に直します。すでに所要時間より速く走る列車は、誤りの一覧の下に注意として出ます。
4. 運用を足し、運行図の列車を順にクリックします(次に入れられる列車の候補からも選べます)。最後に「車庫との回送を足す」を押します。
5. 誤りの一覧が空になったら、「書き出す」から「クリップボードに写す」を押し、ゲームで `/rteditor paste` を実行します。運行中のダイヤは、`/rteditor copy timetable` でページに戻して直せます。

列車の欄の「運休しない」で、遅れた列車をダイヤに戻すときにも運休しない列車(終電など)の印を付けられます。停車の行では、そこで待つ列車と、その列車が出る(通る)駅、最長の待ち時間を決められます。運行図では、待ちを点線の矢印で描きます。

ページは、MOD と同じ規則でダイヤを確かめ、同じ文言で誤りを出します。元に戻す、やり直す、ブラウザへの下書きの保存ができ、言葉は日本語と英語です。

## 設定

設定はワールドごとで、ワールドフォルダの `serverconfig/createrealtimeschedule-server.toml` にあります。クライアントは、接続している間、サーバーの値を使います。

| 設定 | 既定値 | 内容 |
| --- | --- | --- |
| `sync_sky` | `true` | 空を時計に合わせます(上の「空」を参照) |
| `start_time` | `"06:00"` | 保存された時計がないワールドで、時計が始まる時刻 |
| `align_on_start` | `false` | サーバーを起動するたびに、時計をサーバーの時刻に合わせます |
| `default_minimum_stop_seconds` | `20` | 時刻表の画面で、新しい Real Time of Day 条件が最短停車時間として最初に持つ値(0〜600)。すでにある条件は自分の値を保ちます。ダイヤの運用を走る列車も、最低この時間は止まります。ダイヤが停車か駅に最短停車時間を持つときは、そちらを使います |
| `duty_lead_seconds` | `60` | ダイヤの運用の最初の発車の何秒前(0〜3600)に、列車を運用に入れるか |
| `max_wait_seconds` | `300` | ダイヤで待つ列車を、自分の発車の時刻から何秒(0〜3600)まで待つか。待つ列車がそれより遅れる見込みなら、すぐに出ます。ダイヤの待ちが `max_wait` を持てば、そちらを使います |
| `recovery_threshold_seconds` | `600` | ダイヤの運用を走る列車が何秒(0〜7200)より遅れたら、列車を運休してダイヤに戻すか。出発の時刻までに空いた列車がない運用を、どこまで遅れて出すかにも使います(上を参照)。0 にすると、どちらもしません。遅れた列車はそのまま走り、そういう運用はその日は運休です |

## 確認していること、いないこと

テスト(`./gradlew test` と `./gradlew runGameTestServer`)で確認しているのは次のとおりです。時計の計算、時計の保存と送信、空の同期、コマンド、条件の規則と枠のつなぎ方、条件を待っている列車の保存、一直線に並んだ3つの駅を実際の線路で走る列車(早着と遅着)。ダイヤでの運行では、ダイヤの読み込みと保存、周回線の線路で車庫の2本の列車が発車の順に運用へ入って車庫に戻ること、各駅をダイヤの時刻に出ること(発車は、列車が実際にホームを離れた時刻で記録します)、遅着の回復、基準より遅れた列車を駅で待たせて、あとの停車から出し、そのあいだの列車を運休すること(待たせるかどうかの規則は、一つずつ外すと落ちる単体テストでも確かめています)、空いた列車がない運用が、ほかの運用が戻した列車で遅れて出ることと、遅すぎて出られずに運休になること、始まっているはずの時刻のあとにダイヤを読み込んだ運用が遅れて出ること、各駅停車が快速の通過(最後の車両が駅を過ぎたこと)や、同じ駅からの発車を待って出ることと、走らない列車や最長の待ち時間を過ぎた列車は待たないこと、時刻表を入れられた列車の中断。運行図では、実際の線路から求めた駅の間隔、クライアントに送る時刻、線の作り方。編集ページでは、MOD と同じ誤りを見つけること(Java と Node の両方のテストが同じテスト用ダイヤを読みます)、同じ JSON を書き出すこと、ゲームと同じに線を描くこと、ページのコードで作ったダイヤが実際の線路で時刻どおりに走ること、クリップボードのコマンドのサーバーの側。

まだ確認していないのは次のとおりです。

- 周回線、カーブ、信号、複数の列車を、実際の線路で動かすこと
- 時刻表の画面で、設定の行がどう表示されるか(コンパイルしただけです)
- 専用サーバーで、複数のプレイヤーが同じ時刻と空を見られること
- この MOD を持たないクライアントが、入れているサーバーに入れないこと
- クライアントが入るときに、サーバーの `default_minimum_stop_seconds` を受け取ること。NeoForge のコードでは、入ってくるクライアントにサーバーの設定ファイルを送っていますが、実際のクライアントでは試していません
- ダイヤでの運行を、サーバーの再起動をまたいで続けること(運行の状態を保存して読み戻すことだけを確かめています)。信号のある線路で、複数の列車が同じ線路を走る運行。走っている列車が脱線したとき
- 信号があり、ほかの列車も走る線路で、遅れた列車を駅で待たせること。運休した列車が、実際のクライアントの運行図でどう見えるか
- 運行図のキーとマウスの操作の一つ一つ(運行図そのものは実際のクライアントで見て、計画と実績の線が重なること、時刻がサーバーの時計と合うことを確かめています)
- クリップボードのコマンドと `/rteditor` を、実際のクライアントで使うこと。`file://` で開いた編集ページの動き(Chromium のブラウザで `http://localhost` から使うことは確かめています)。GitHub Pages のページ(Pages を有効にして、main に入ってから公開されます)

## ビルド

Java 21 が必要です。`./gradlew build` で `build/libs` に jar ができます。最初の実行では Minecraft、NeoForge、Create をダウンロードするので、時間がかかります(10分ほど)。

```
./gradlew test                # 単体テスト
./gradlew runGameTestServer   # ゲームテスト(テスト用サーバーで実行)
./gradlew runClient           # 開発用のクライアント
./gradlew runServer           # 開発用のサーバー。最初の起動のあと、run/eula.txt で EULA に同意する
```

GitHub Actions が、`main` 向けのプルリクエストと、`main` への push のたびに、`./gradlew build` と `./gradlew runGameTestServer` を実行します([.github/workflows/build.yml](.github/workflows/build.yml))。

Create Train Next の制限速度標識の下を走る列車を測るゲームテストは、Create Train Next をビルドした jar を `libs/createtrainnext.jar` に置いたときだけ走ります(git は `libs/` を含めません)。Create Train Next にはリリースがなく依存にできないので、CI では走りません。
